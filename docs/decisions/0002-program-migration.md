# Source-bound program migration

The registered migrated-exact policy is a new semantic version. Legacy rules,
profiles, schemas and canonical bytes remain pinned. It retains established
set counts, current target vectors, saved setups, explicit loads and stricter
source safeguards while using native exact progression going forward. Source
calendar phases, calibration and qualifying counters remain archival data.
Imported current state is a checkpoint, never evidence of a suitable historical
native workout. Imported continuation uses two minutes between sets and three
minutes between movements.

A `ProgramMigrationDocument` contains an `external-program-source-v1` archive
and a source-bound checkpoint. The archive preserves exact file bytes, raw
observations and typed source bindings. The native preview requires an explicit
goal, any unresolved current-load confirmation from the fixed movement catalog,
and acknowledgement of the disclosed transition. A future load confirmation
never changes ambiguous historical load basis or certifies recovery.

The repository creates a deterministic new program/dataset/root identity from
the document and semantic selection. The reviewed store fingerprint covers
admitted heads, drafts and immutable object checksums. Archive, root, head and
outbox changes share one transaction. Any protected draft, stale fingerprint,
invalid source or occupied conflicting identity rejects without a partial import.
Repeated imports preserve the original acceptance clock and subsequent native
progress. Explicit adoption persists active selection and keeps prior programs
exportable. Prior pauses, higher reserve and dormant safety families must be
matched conservatively before adoption; unmappable protection blocks selection.

The source archive occupies the existing portable profile/archive slot with an
explicit recognized kind. Every migration root requires that dependency and
replays the pure checkpoint reducer. Backup and recovery compare full returned
state, prescription and decisions. Missing source archives remain incomplete;
changed source references or forged hash-correct projections fail admission.
No outer backup format or SwiftData schema rewrite is needed.

Each repository owns a bounded immutable source-admission and root-replay cache.
Keys cover actual source, rule, profile, source-profile and root bytes; mutable
heads, drafts and returned projections are validated on every capture. Closing
the repository clears the cache. Selection and recovery proof use the same
repository context off the presentation thread. Standalone backup/recovery
validation retains full cold admission.

History merges native workouts and source-date observations with an external
origin label. Raw nulls, ambiguous tokens, original notes and no-exercise records
remain available in source detail and exact original-file export. Source dates
do not acquire invented timing, native prescriptions or effort classification.

Source recovery requirements demand an explicit fresh review at each required
movement introduction. The draft retains the checked session clock and source
hash; Finish freezes the same typed attestation. Native completion admission
checks it again. A stop can preserve unconfirmed raw observations without
receiving progression credit or fabricating recovery approval.

For a bounded local proof, build `PlentyStrongCrashHarness` with the installed
Xcode toolchain and run:

```text
PlentyStrongCrashHarness migration-proof <nonexistent-disposable-directory> <repository-root> <migration-json> <dry-run-selection-json>
```

The harness accepts explicit local paths, creates fresh stores, and validates
root-only import, repeat identity, reopen, native backup/restore and shuffled
recovery. It writes a private report with source counts/checksums, current vectors
and phase timings. The selection is a dry-run condition, not user approval.
It does not read an installed store, generate historical native workouts or
connect to an account. Public fixtures and UI screenshots are synthetic.

For one cold and two warm read-only snapshots of that completed disposable proof:

```text
PlentyStrongCrashHarness migration-snapshot-timing <completed-proof-directory> <repository-root>
```
